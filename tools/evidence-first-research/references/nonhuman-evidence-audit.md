# Non-human evidence audit for research manuscripts

Use this recipe when a manuscript needs stronger empirical support before human annotation is available. The goal is to add reproducible **artifact and machine-diagnostic evidence** without converting it into semantic or effectiveness claims.

## Evidence layers

Keep these layers separate in reports and prose:

1. **Provenance and recoverability** — source/asset existence, hashes, dimensions, page markers, image references, inventory mapping.
2. **Condition-package construction** — valid package cells and controlled differences among T, TL, and TLV.
3. **Leakage warnings** — lexical overlap or extracted-text availability; warnings only, never semantic leakage judgments.
4. **Machine diagnostics** — completion, answerability/output identity, transcript evidence, and failed-route bookkeeping.

None of these establishes positive TL/TLV labels, semantic sufficiency, modality necessity, human agreement, GAR/MNP/TLR/ERR/FAR, accuracy, or superiority.

## Procedure

### 1. Freeze scope and denominators

Record separately:

- source documents and pages;
- extracted assets and shortlist assets;
- frozen item proposals;
- conditions per proposal and total item-condition cells;
- model/provider runs.

Never merge counts from different pipeline stages (for example, source-ingestion candidates and later frozen proposals).

### 2. Run deterministic integrity checks first

For each relevant source and asset, verify:

- file presence and parse/decode success;
- SHA-256 against recorded hashes;
- byte count and image dimensions against manifest;
- source-inventory mapping;
- extracted page marker and image reference;
- non-empty extracted page segment.

Report unmapped assets explicitly rather than silently dropping or promoting them.

### 3. Verify matched-condition semantics

For every T/TL/TLV cell, check:

- package JSON parses and IDs/condition declarations match;
- all packages have the intended text representation;
- T and TL contain no image fields;
- TLV contains the intended visual asset;
- T→TL differences are documented;
- TL and TLV text hashes are identical when the intended contrast is pixels only.

This last check is high-value evidence that the pixel condition does not quietly alter text.

### 4. Screen leakage conservatively

Lexical answer-token overlap is a warning, not proof that the answer relation is text-recoverable. Always give denominators (for example, warning cells / screened cells).

Tokenizer and normalization choices can produce conflicting totals. Before publication:

- select and document one canonical tokenizer/scorer; or
- report only warning-cell prevalence and omit token totals.

Never combine totals generated by incompatible procedures.

### 5. Run machine diagnostics safely

- Use one independent request per item-condition cell.
- Exclude reference answers from prompts.
- Do not retain cross-condition conversation state.
- Freeze prompt version, temperature, package hashes, and model/provider identifier.
- Keep different model/provider runs separate.
- Keep failed reruns separate from completed archived outputs.

Cross-run answerability agreement or answer identity is **bookkeeping**, not reliability or reproducibility when model/provider states differ.

### 6. Inspect reference-matching answers

Exact match can be correct by prior, aggregate prose, or underdetermined inference. Inspect answer atoms, evidence references, and rationale. Prefer manuscript wording such as:

> This is a warning of a reference-matching answer unsupported by year-specific evidence; answer matching alone cannot establish semantic sufficiency or modality necessity.

If only `evidence_refs` list values, say they “listed” the values; do not say the whole response “cited” them if the rationale does not.

### 7. Update manuscript and verify package

Add a table captioned as deterministic readiness/machine-bookkeeping evidence, not effectiveness results. After editing:

- build with the venue template;
- scan for LaTeX errors, undefined citations/references, and overfull boxes;
- verify page size/count and embedded font types;
- synchronize submission source/PDF/reports;
- rebuild ZIP, test archive integrity, and record SHA-256;
- use an independent critic to compare every manuscript count and phrase against reports.

## Claim boundary checklist

Allowed before human annotation:

- source and package integrity;
- recoverability and mapping counts;
- controlled package-difference counts;
- warning prevalence;
- completed-request bookkeeping;
- cross-run output identity/answerability counts with caveats;
- transparent infrastructure failure counts.

Blocked before human annotation/adjudication:

- positive TL/TLV counts;
- semantic sufficiency or modality necessity;
- effectiveness/accuracy or multimodal gain;
- GAR, MNP, TLR, ERR, FAR;
- inter-annotator agreement;
- statistical superiority.

## Operational boundary

When the user explicitly says human work is not yet needed, do not read, populate, or modify annotator/adjudication files. Exhaust the deterministic and machine-diagnostic evidence first, then state exactly what remains human-dependent.
