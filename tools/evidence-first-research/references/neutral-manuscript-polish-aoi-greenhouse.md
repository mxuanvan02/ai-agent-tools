# Neutral manuscript polish: bài AoI-greenhouse session notes

Use when người dùng asks to make a manuscript/slide deck more focused, neutral, and less like it is attacking baselines.

Session-specific lessons:
- If a conceptual comparison figure exists only to show AoI/AoII/other baselines are "blind" or weak, remove it unless it is essential to the method. Keep prior work lineage in Intro/Related Work and quantitative comparisons in Evaluation.
- Reframe prior work as reference operating points or inherited perspectives, not targets to beat. Preferred wording: "freshness/incorrectness-oriented scheduling", "primary signal", "operating trade-off", "threshold-weighted objective".
- Avoid/replace loaded wording: `blind`, `not competitive`, `worse`, `trail`, `failure mode`, `vì sao thua`, `kết quả phủ định`, `tấn công`, `straw-man` in final manuscript prose unless explicitly doing internal review.
- When người dùng says "phần ở giữa" or "lan man", inspect the central sections (Methodology, Evaluation, Theory) for long explanatory paragraphs, tail/worst-case digressions, and aggressive interpretation paragraphs. Prefer one concise neutral paragraph after each table.
- For final handoff, build after the last text edit and send only clean zip/PDF. Audit the zip itself, not only source directories, for old artifacts or removed terms.

Newer lessons (multi-round polish + "rà kĩ lại / lệch đề không"):
- DUPLICATE + MISPLACED SECTION is a common "lệch đề" bug. Here a "Computational Complexity" subsection lived in BOTH Methodology (short, correct) and Theory (5 paragraphs). The theory copy leaked empirical runtime/missed-violation numbers (434ms, 1.06%) into a proof section AND revived adversarial phrasing ("does not match bài AoI-greenhouse's safety", "does not recover the same safety-objective values"). Fix: strip empirical numbers out of the complexity/theory section (point to Evaluation for the head-to-head), keep only computational cost there, and neutralize ("the two methods optimize different objectives" not "does not match"). When asked "ở giữa còn lệch đề không?", first dump the section/subsection map (`grep -nE '\\(section|subsection|paragraph)\{' sections/*.tex`) and look for repeated titles + empirical content sitting in a theory/analysis section.
- Neutralization is ITERATIVE: người dùng re-asks "rà kĩ" several times. Each pass, re-grep for residual loaded tokens (`central finding|strongest|catastrophic|sacrific|bipolar|wins .* loses|complete the picture|uniformly better`) plus the earlier list. "bài AoI-greenhouse wins 27 and loses 3" style win/loss counting reads as triumphal — replace with "the gain is concentrated in contention-heavy windows".
- RESOLVING a confirmed duplicate section (when người dùng picks "gộp / gọn nhất"): don't just trim both copies — MERGE to one location and delete the orphan. Sequence that worked: (1) `clarify` offering merge vs keep-structure vs minimal options, let người dùng pick; (2) delete the redundant subsection that repeats earlier material (here §III-B "Centralized Polling" re-stated the System Model estimator+channel); (3) fold the one useful sentence from the orphan into the surviving section (added an `O(KN|S|^3)` vs `O(N\log N)` contrast line into the Methodology complexity subsection, pointed runtime numbers to the Evaluation table); (4) remove the `\input{sections/05b_complexity}` from main.tex; (5) fix dangling cross-refs (`\ref{sec:complexity}` now resolves inside Methodology); (6) `cp` the orphan file into `_backups/<ts>/` THEN `rm` it (never delete research source outright); (7) `latexmk -C` then full rebuild to confirm the removed file is truly gone and page count drops (16→15 here), grepping the final pass for `Reference.*undefined`=0. latexmk prints no "Output written" line when it thinks targets are up-to-date — run `latexmk -C` first to force a clean build and actually see the page count.
- When a `patch` old_string fails to match (whitespace/escaping in dense LaTeX), fall back to `execute_code` doing literal `str.replace` over the file with a missing-count check; it is more robust for multi-paragraph neutral rewrites than fighting fuzzy match.

Highlight PDF against a PRIOR revised baseline (not original draft):
- When the project already has `_review_artifacts_final/revised_flat.tex` from an earlier round, diff the CURRENT flat against THAT to show only this round's removals/edits: `latexpand main.tex > current_flat.tex` then `latexdiff --type=UNDERLINE revised_flat.tex current_flat.tex > highlight.tex`, copy `figures/` + `references.bib` alongside, then `pdflatex → bibtex → pdflatex → pdflatex`. `--type=UNDERLINE` survived math here where CFONT/soul did not. Deliver the highlight PDF plus the diff `.tex` so người dùng can inspect source.

Section-by-section scope audit ("rà tiếp từng mục, mục nào nội dung đúng trọng tâm của mục đấy"):
- This is a distinct request from neutralizing: go through EACH section/subsection and verify its content matches its own heading (no drift, no duplication). Report as a table `mục | nội dung | đúng trọng tâm? (✓/⚠️)`. Cover the whole paper across passes if asked repeatedly — người dùng iterates section group by group (middle sections, then Abstract/Related Work/Appendix).
- Flag-but-don't-force items that are intentional, not bugs: e.g. §VoU saying "rather than assuming Gaussian tails ... we compute empirical P_vio" next to "Gaussian form used for analysis" LOOKS contradictory but is the deliberate analysis-vs-deployed split — note it as "observed, not a defect" and leave it.
- Appendix proofs should contain ONLY proof detail for the theorems/props in the theory section; Related Work should be lineage/positioning (neutral); Abstract should mirror the contribution order. Confirm each, don't rewrite what already conforms. "Nothing to change this pass" is a valid audit outcome to report (then act only where a real drift/duplicate is found).

Step-by-step proof walkthrough (presentation preference, NOT a manuscript edit):
- When người dùng says "trình bày step by step đối với phần chứng minh ... làm rõ từng công thức", he wants each proof explained as numbered steps (B1/B2/B3), each displayed equation followed by a one-line plain-language gloss (`>` quote), a shared symbol glossary table up front, and a boxed final result. Same pedagogical shape as the Beamer proof-sketch slides (manuscript-to-beamer-slides.md §5f) but delivered as a chat walkthrough.
- Order proofs easy→hard (suppression lemma → leading-order proposition → service-gap theorem → negative bounded-deficit proposition). Include the Mills-ratio expansion, ES/P_vio→σ·ε ratio, ε-expansion factoring, debt-dominance counting argument as the worked steps.
- This is ANSWER mode (explaining existing proofs), not EXECUTE. Do NOT modify the .tex unless người dùng then says to embed it. End by offering the two follow-ups he'll likely want: (a) expand the Appendix proofs to this verbosity, or (b) a standalone "proof walkthrough" PDF keeping the manuscript terse — let him pick.

Concrete rewrite patterns:
- "Why X is not threshold-aware" -> "How bài AoI-greenhouse represents threshold risk relative to freshness/estimation/query signals".
- "X is worse / not competitive" -> "X optimizes a different operating objective; under this threshold-weighted evaluation, bài AoI-greenhouse reports lower loss".
- "This proves baseline fails" -> "This supports using the calibrated exit-probability term in this regime".
- Long multi-finding baseline paragraph -> 2-3 sentences: table position, trade-off, objective alignment.
